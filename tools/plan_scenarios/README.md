# 도면 분석 실전 시나리오

플랫폼마다 평면도 양식이 달라 분석이 틀리는 문제를 막는 자가 점검 고리.

- `fixtures.js` — 정답을 아는 평면(전용 76.84㎡, 방 3·욕실 2·발코니 1)을 양식별로 그린다: KB식(짙은 벽·타일 줄눈), 네이버식(비침 글자·연한 창·전용 글자), 네이버 치수선식, 부동산114식(방마다 면적 글자·가는 선 발코니), 설계 도면식(속 빈 벽). 고객 도면은 쓰지 않는다.
- `scenarios.json` — 10개 시나리오(양식 × 전달 방식: 파일, 화면 캡처, 휴대폰 사진, 작은 미리보기, 흐린 확대, 큰 원본, 글자 없음, 다른 평형 면적 입력, PDF 스캔식).
- `run.js` — 실제 분석 도구(assets/plan_*.js)로 돌려 점수(방·욕실·발코니 수, 이름, 면적 오차, 척도, 창, 직각)를 매긴다. `baseline.json` 보다 8점 넘게 떨어진 시나리오가 있거나 평균이 4점 넘게 떨어지면 실패.
- 깃허브 작업 `도면 분석 실전 시나리오` — 분석 도구가 바뀔 때와 매일 04:17 에 돌고, 올린 바뀜 때문에 나빠지면 그 바뀜을 자동으로 되돌린다.

돌리기: `node tools/plan_scenarios/run.js --shots 폴더` · 좋아진 뒤 기준 올리기: `--write-baseline`

새 버그를 찾으면: 그 양식·전달 방식을 `fixtures.js`/`scenarios.json` 에 시나리오로 먼저 넣고(실패 확인) → 고치고 → 기준을 올린다.
알려진 한계: S09(글자 없는 도면은 규칙 방식이라 방을 많이 쪼갬), S10(설계 도면은 척도만 맞음 — 학습 모델이 올라오면 방 나누기 기준 추가).
