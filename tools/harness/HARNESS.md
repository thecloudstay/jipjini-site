# 도면 변환 자가 개선 고리 (하네스)

2026-11-12 대표 지시: 「그리는 게 중요한 게 아니라 버그 규칙을 찾아서 앞으로 그렇게 안 되도록」, 「스스로 규칙을 찾아내고 그 규칙을 계속 반영해 가면서 일할 수 있도록 자가 개선 루프 엔지니어링 하네스 구축」.

대상: 네이버 평면도 → 집지니 캐드 도면 변환(`tools/plan_trace.py` → `data/plans` · `data/cad`).
(채점 고리 `D:\croll\코드\plan_loop.py` 는 누리집 그림 읽기 `assets/plan_*.js` 담당 — 이 고리와 따로 돈다.)

## 한 바퀴

| 단계 | 하는 것 | 도구 |
|---|---|---|
| 1 표본 | 고정 표본 28장(`D:\croll\자료\변환표본\`, 방자료.json 포함) + 탐색 표본 10장(`D:\croll\자료\원본_목록.csv` 에서 무작위, 이미 본 것 제외) | 대표 컴퓨터에서 가져옴 |

| 8 관문 | 고친 판을 같은 표본으로 다시 측정해 견준다. **문 안전(R5)은 하나도 늘면 안 됨**, 다른 규칙도 1 넘게 늘면 안 됨, 무게 합이 줄어야 함, 다른 곳 수가 5% 넘게 늘면 안 됨, 고친 규칙이 줄어야 함 | `run.py 관문` (0=남김 1=버림) |
| 9 반영 | 남김: 자료·캐드 다시 만들기 → `run.py 기준` → 합치기. 버림: 코드 되돌림, 일지에 이유 | 깃허브 |

`일지.md` 에 판마다 한 줄(무게·다른 곳 수 전후, 남김/버림 이유)이 쌓인다. 버린 고침은 다시 하지 않는다.
`기준.json` = 마지막으로 남긴 판의 규칙별 개수 — 다음 판의 비교 대상이고 「얼마나 좋아졌나」의 근거.

## 지킬 것
- 원본 평면도 그림은 저장소·합치기 요청·보고에 넣지 않는다(좌표·숫자만). 가져온 사본은 일이 끝나면 지운다.
- 관문을 통과하지 못한 고침은 합치지 않는다. 관문 기준을 느슨하게 고치지 않는다(조이는 것은 된다).
- 「무시」로 넣은 표식은 이유를 반드시 적고, 보고에 함께 알린다(대표가 뒤집을 수 있게).
