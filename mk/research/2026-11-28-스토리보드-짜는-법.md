# 스토리보드·웹툰 영상 짜는 법 (2026-11-28, 대표 「스토리보드는 전문가 방식 조사 후」 「웹툰처럼, 부부 형식」 「깃허브 조사부터, 직접 제작 가능하게」)

## 출처
- 캡컷 「60초 이야기 구조」: 0~3초 갈고리, 7초까지 무슨 이야기인지, 7~21초 갈등, 절반 전에 방향 전환, 끝은 약속한 결과. 한 영상에 변화 하나. 주장에는 증거 화면 — https://www.capcut.com/create/short-form-video-storytelling-60-second-arc
- 블레어미디어 「영상 이야기 틀 비교」: 고객 후기는 줄인 영웅의 여정(평범한 일상 → 계기 → 시련 → 변화 → 귀환). 고객이 주인공, 업체는 길잡이. 「친절했어요」 같은 일반 칭찬은 못 씀, 의심과 실패할 뻔한 순간이 있어야 함 — https://blaremedia.net/storytelling-frameworks-for-video/
- 캡틴후크 「스토리와 스토리텔링의 차이」: 감정 목표 하나, 구체 사물로 감정 전달, 고백형으로 열기, 절정 앞에 정적, 끝은 구호 대신 여운 한 문장 — https://maily.so/captainhook/posts/92zewnwpzep
- 깃허브 영상 스토리보드 스킬: 컷마다 목적·구도·움직임·소리·길이, 6~18컷, 왜 이 순서인지 근거 — https://github.com/aicontentskills/ai-video-storyboard-skill
- 애니쿠쿠 「모션 코믹 제작 순서」: 한 컷은 한 역할(소개·공개·행동·반응), 캐릭터 기준 자료 먼저, 넓게·중간·얼굴·반응 섞기, 음성 먼저 → 컷 길이, 한 컷에 움직임 하나 — https://anikuku.com/ko/blog/ai-motion-comic-maker-guide
- 라마젠 「캐릭터 시트」: 얼굴·머리·체형·옷·소품·색을 한 번 고정하고 형식에 맞춰 표현만 바꿈 — https://llamagen.ai/en-in/blogs/one-character-sheet-comic-webtoon-storyboard

## 그림은 어떻게 구하나 (조사 결과)
| 방법 | 판정 |
|---|---|
| 오픈 핍스(깃허브 CeamKrier/react-peeps, 그림은 파블로 스탠리 CC0) — 표정 33·머리 51·자세 65가지 조립 | **채택.** 한도 없음, 캐릭터가 컷마다 같음, 대표 「마음에 들어」 |
| 오픈 두들스(lunahq/react-open-doodles, CC0) — 전신 장면 33가지 | 보조 |
| 캔바 그림 생성(캐릭터 시트 참조) | 품질 가장 좋음, 5장에서 한도 초과 |
| 히그스필드 그림 생성 | 유료 요금제부터 |
| 폴리네이션스(무료) | 붐빔·무료 한도 도달로 실패 |
| 작업 공간에서 직접 생성(stable-diffusion.cpp·fastsdcpu) | 사양·모델 내려받기 문제로 불가 |
| 클로드가 코드로 직접 그리기 | 가능하지만 대표 「너무 구려」 → 쓰지 않음 |

## 지키는 규칙
1. 대본(나레이션)부터: 고백형 갈고리 → 발품·갈등 → 포기 직전(정적) → 계기 → 증거 화면 → 시련(추가 비용) → 변화 → 여운 한 문장.
2. 음성을 먼저 만들고 컷 길이를 음성에 맞춘다(감정 지시 음성).
3. 컷마다 역할 하나. 인물 컷과 증거 컷(실제 화면)을 섞고, 증거 컷에는 반응 얼굴을 동그란 딱지로 얹는다.
4. 금액·대화는 「이야기용 예시」, 전체는 「고객 여정을 재구성한 이야기」라고 화면에 적는다(실제 후기처럼 보이게 하지 않는다).
5. 말풍선은 짧게 한마디, 나레이션 자막은 컷 아래에 한 문장 통째로.
